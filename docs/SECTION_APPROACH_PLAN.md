# 새 섹션 기획안 — "융합형 개발" (Approach)

이 문서는 로드맵 3단계(직접 손코딩)에서 만들 **새 섹션의 기획 확정안**이다.
기획은 AI와 함께 정했고(개발 실력과 직접 관련이 적은 부분), **구현은 개발자가 직접** 한다.
(로드맵·규칙: `NEXT_ROADMAP.md` §3, `CLAUDE.md` / 애니메이션 사용법: `FRAMER_MOTION_GUIDE.md` §2.4·§3 / 접근성: `A11Y_CHECKLIST.md`)

> 상태: **기획 확정, 구현 착수 전.** 구현 중 세부는 바뀔 수 있음 — 바뀌면 이 문서를 갱신한다.

---

## 1. 목적 / 콘셉트

- Hero가 **"누구"**라면, 이 섹션은 **"어떻게 일하는 개발자인가"** — 이 사람의 **스펙이 아니라 개발 방향**을 소개한다.
- Hero에 이어 그 사람을 한 번 더, 더 상세히 소개하는 자리.
- 기존 `Skills` 섹션(기술 스택 = 스펙)과의 **차별점**이 이 섹션의 핵심: 여기선 "무엇을 쓰는가"가 아니라 **"어떤 태도로 개발하는가"**를 말한다.

## 2. 콘텐츠

- **메인 카피**: "나는 **융합형** 개발을 지향합니다"
- **벤 다이어그램**: 세 원 = **기획 · 디자인 · 개발**, 세 원의 **교집합 = "융합형"**
  (교집합 라벨이 메인 카피의 그 단어와 **같은 단어**가 되도록 맞춘다 → "세 영역이 합쳐져 이 단어가 됐다"는 서사)
- 카피는 로드맵 4단계에서 실제 문장으로 다듬을 수 있음(현재는 방향 확정 수준).
- **디자인 시안(끝 상태)**: Figma 파일 내 `approach` 프레임으로 생성됨(기존 디자인 오른쪽). `// APPROACH` 라벨 + "나는 융합형 개발을 지향합니다"("융합형" 액센트 강조) + 기획·디자인·개발 벤 다이어그램(중앙 교집합 "융합형"). 색·폰트·간격은 기존 값(accent #6366F1, Geist / Geist Mono, bg #0A0A0A)과 일치. **구현 시 좌표·크기·색은 이 프레임을 레퍼런스로 참조.**

## 3. 인터랙션 = 핸드오프 모션 스펙 (framer-motion으로 구현)

> 이 시퀀스의 **끝 상태**는 §2의 Figma `approach` 프레임이 레퍼런스다. 아래는 그 정지 화면에 붙는 "모션 코멘트"에 해당한다 — 스크롤 연동은 Figma로 표현 불가하므로 글 스펙으로 넘긴다.
> **트리거**: 섹션이 뷰포트에 들어온 뒤의 스크롤. **타이밍·이징 수치는 구현 단계에서 직접 결정**(스펙은 "무엇이 어떤 순서로"까지만).

1. **진입**: 메인 텍스트가 먼저 페이드인 — 기존 재사용 래퍼 `FadeIn` 활용.
2. **스크롤 연동 병합 (핵심)**: 세 원이 **스크롤 진행도(0→1)에 따라** 3방향에서 중앙으로 모인다.
   - `useScroll`(섹션 기준 `target`/`offset`) + `useTransform`으로 진행도를 각 원의 좌표에 매핑.
   - **자동 재생 병합은 없음.** 병합의 드라이버는 스크롤.
   - **진행은 한 방향(되감김 없음).** 스크롤을 내리면 진행도에 따라 모이지만, **다시 올라가도 되감기지 않고** 도달한 최고 상태를 유지한다. 구현은 `scrollYProgress`를 직접 쓰지 않고 **여태 도달한 최댓값만 기억하는 단조 증가 진행도**(예: `useMotionValueEvent`로 최댓값 latch)를 드라이버로 삼는다.
3. **완료 시점(진행도 ≈ 0.8~1)**:
   - 메인 카피의 **"융합형"에 액센트 마커 하이라이트**가 왼→오로 쓸고 지나가며 글자가 액센트 색으로 남음(1회).
   - 세 원의 **라벨(기획/디자인/개발) 등장**.
4. 인터랙션 밀도: 스크롤에 원 3개 좌표 + 라벨 + 하이라이트가 함께 연동되어 "인터랙션이 많은" 느낌을 낸다.

### 접근성 / 모션 최소화 (reduced-motion)

- `prefers-reduced-motion`이면 **스크롤 연동을 끄고** "이미 합쳐진 정지 상태 + 라벨 보임 + 단어 강조됨"으로 렌더.
- 이 정지 상태 = **마크업만으로 완결되는 최종 형태**와 같게 설계한다(마크업 먼저 세우면 곧 이 상태가 됨).
- `useReducedMotion` 가드는 처음부터 설계에 포함(기존 `FadeIn`/`Hero` 패턴 참고).

## 4. 반응형 (모바일 우선 규칙 준수)

- **데스크탑(md+)**: 겹치는 벤 다이어그램(원 3개, 스크롤 병합).
- **모바일(md 미만)**: 벤 대신 **모서리 둥근 사각형 3개(기획/디자인/개발)를 세로로 적층 → 아래로 화살표 → "융합형" 박스**.
  "겹침(교집합)"을 **선형(합쳐짐 → 결과)** 으로 번역한 폴백. 스크롤 병합 연출은 데스크탑 위주(모바일은 정적/단순 페이드).
- 좁은 화면에서 겹친 원 + 텍스트가 뭉개지는 걸 피하는 게 목적.

### 폴백 구현 방식 — 확정 (2026-07-22)

- **두 블록 분리 + 데이터 공유**: 벤(데스크탑)은 `hidden md:block`, 스택(모바일)은 `md:hidden`.
  절대좌표 벤과 흐름 기반 세로 스택은 구조가 너무 달라 **한 DOM 반응형은 오히려 복잡** → 각 블록을 단순하게 유지.
  DRY는 마크업이 아니라 **`circles` 배열을 두 블록이 함께 `map`** 해서 해결(진실의 출처는 배열 하나).
- **접근성은 B 방식으로 통일**: 두 시각 레이아웃(원/스택)은 **둘 다 장식(`aria-hidden`)**, 의미는
  **sr-only 보완 문장 하나**("기획, 디자인, 개발이 합쳐진 융합형")가 **뷰포트와 무관하게** 커버.
  → 모바일 박스의 텍스트를 콘텐츠로 노출하면 sr-only 문장과 **중복 낭독**되므로 노출하지 않고 장식 처리.
- **화살표는 장식**: `aria-hidden` 아이콘(예: `react-icons`의 아래 화살표). 개발 박스 하나가 아니라 **세 박스 묶음 → 융합형**으로 읽히게 배치.
- **반응형 전환은 CSS 가시성으로**(`hidden`/`md:hidden`) — `matchMedia` 등 JS 분기 없이 → 하이드레이션/SSR 불일치 원천 차단.

## 5. 기존 코드에 물리는 지점 (규칙 준수)

- 섹션 id = **`approach`** → `<section id="approach">` (앵커 `#approach`).
- **Header 네비에 링크 추가**(라벨 "Approach" → `#approach`) + `page.tsx`에서 **Hero 다음**에 배치(순서: Hero → 이 섹션 → Projects → Skills → CTA).
- 헤딩 계층: Hero가 `h1`이므로 이 섹션 제목은 **`h2`**.
- 공통 컨테이너 `container-page` 사용 / **디자인 토큰만**(색 하드코딩 금지, 하이라이트도 `accent` 토큰) / 반복 데이터(세 축)는 **배열 + map** / `"use client"`는 인터랙션 컴포넌트에만.

## 7. 난이도 메모

- **스크롤 연동 병합**은 이 프로젝트에서 검토한 인터랙션 중 **가장 어려운 축**이며, 이것이 **첫 손코딩 섹션**이다.
  `useScroll`의 `target`/`offset` 잡기, 진행도→좌표 매핑, 스크롤 거리 확보(섹션 높이 or sticky) 등에서 막힐 수 있음 — 각오하고 진행.
